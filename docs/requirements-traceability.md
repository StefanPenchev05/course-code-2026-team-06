## Reading status and evidence

MoSCoW scope: **Must** = MVP, **Should** = Release 1, **Could** = optional, **Won't** = excluded. NFRs are treated as Must quality constraints for the included scope; this does not claim their targets have been verified. FR23 is now Must.

Status vocabulary: **Implemented and verified**, **Partially implemented**, **Planned**, **Blocked**, **Excluded**, **Not independently verified**. No end-to-end requirement is labelled Implemented and verified in this review: source and existing tests were inspected, not executed, and the frontend/production gates remain. Partially implemented means concrete backend behavior exists with test artifacts, not that all acceptance criteria pass or that deployment is ready. Blocked identifies an essential external dependency. Planned has no complete workflow. Not independently verified identifies absent measurement evidence. Excluded is intentional scope.

Evidence links below identify concrete services, persistence and tests. A test file's existence is evidence of coverage intent, not a fresh passing run. GitHub state is a planning snapshot, never proof of implementation. U01 remains an unresolved product decision; U02–U04 are university/policy approval gates. No application code, migrations or production settings change in this task.
